## 固定签名

正式包名为 `io.github.tbeimu.gongxiaozhu`，调试包名带 `.debug`。证书 SHA-256 记录在根目录 `release-signing.sha256`，构建和更新安装时均核对。

当前开发机密钥备份位于被忽略的 `local/signing/gongxiaozhu-release.p12`，口令位于 DPAPI 加密的 `release-password.clixml`；不得提交这些文件或替换发布密钥。迁移开发环境前应安全备份，DPAPI 文件不能保证在另一台电脑解密。

GitHub Actions 使用以下 Secrets：

- `GXZ_SIGNING_KEYSTORE_BASE64`
- `GXZ_SIGNING_STORE_PASSWORD`
- `GXZ_SIGNING_KEY_ALIAS`
- `GXZ_SIGNING_KEY_PASSWORD`

本地构建通过环境变量提供密钥路径及口令，不放入代码、命令行参数或 `local.properties`。未配置签名的 APK 不能作为正式安装包发布。

## 发布流程

1. 递增 `app/build.gradle.kts` 的 versionCode，修改 versionName。
2. 添加 `docs/releases/vX.Y.Z.md` 中文说明，更新 README 的版本与实际验证结果。
3. 使用 Gradle Wrapper 运行相关测试、Lint 和签名构建；检查暂存差异及敏感数据。
4. 提交并推送，确认“安卓检查”通过后创建匹配版本的标签并推送。
5. “发布正式 APK”工作流再次检查、构建并核对版本、证书，生成附件后创建 Release。

已公开版本不替换 APK、标签或附件；修复发布更高版本号。源码回滚使用 `git revert`，不强制推送。已发布的 `docs/releases/` 保留历史事实及与原 update.json 一致的说明。

## 附件与在线核验

每个 Release 提供：

- `gongxiaozhu.apk`：固定签名正式包。
- `SHA256SUMS.txt`：实际 APK 的 SHA-256。
- `update.json`：从实际 APK 与中文说明生成的更新信息。

`scripts/create-update-metadata.py` 使用 SDK 的 `aapt` 读取版本、包名及 minSdk，计算大小与摘要。schemaVersion 为 1，字段包含 versionName、versionCode、packageName、minSdk、apkSize、apkSha256、releaseNotes。

客户端读取 `releases/latest/download/update.json`，选定版本后从固定标签下载 APK；证书信任来自随 App 构建的摘要，不信任服务器宣告的新证书。发布后下载三个附件，核对真实版本、包名、证书、大小、摘要及说明，另确认 latest 入口一致。
