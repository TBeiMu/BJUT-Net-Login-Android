# 工小助

面向北京工业大学校园网的 Android 登录助手。

核心目标：连接校园 WiFi 后，打开 App 即可使用已保存的默认账号登录，无需反复填写账号密码。支持学校公共 WiFi 和宿舍光猫 WiFi，提供多个账号的本地加密管理。

> 第三阶段功能及 review 修复已完成：当前 WiFi 识别、公共 WiFi 认证和宿舍两阶段 IPv4 认证已接入，模拟测试与 Android 12 模拟器验证通过。用户初步反馈手机上似乎可用，但尚未记录网络类型、设备系统和认证前后状态，公共／宿舍完整实机验收仍待完成；当前 APK 为联调阶段版。

## 第一版功能

- 支持 Android 12 及以上版本，采用 Kotlin 和 Jetpack Compose。
- 添加、编辑、删除多个账号，设置默认登录账号。
- 使用 Android Keystore 管理密钥，以 AES-GCM 加密保存账号资料；账号数据排除备份。
- 打开 App 时自动登录，可关闭自动登录，也可手动登录或重试。
- 支持公共 WiFi 的 wlgn 认证和宿舍 WiFi 的两阶段 IPv4 认证。
- 显示网络类型、默认账号、认证状态和失败原因。
- 登录请求明确通过当前 WiFi 发送，避免未认证时误用移动数据。

第一版不包含后台常驻、定时保活、IPv6 认证、运营商选择、云端同步或自动连接 WiFi。

## 第二阶段已实现

- 首页显示默认账号、已保存的网络模式和自动登录偏好。
- 账号页支持添加、修改、删除和设为默认；首个账号自动成为默认账号，删除默认账号后选择剩余的第一个账号。
- 备注可选，同一校园网账号不重复保存；账号首尾空格会去除，密码内容原样保留。
- 密码输入默认隐藏，编辑窗口禁止截图；账号列表不显示密码。
- 设置页支持保存自动登录开关和自动识别／公共 WiFi／宿舍 WiFi 模式，界面适配系统深色模式。
- 整份账号资料及设置通过 Android Keystore 与 AES-256-GCM 加密，使用随机 IV，原子写入 `noBackupFilesDir`，并禁用备份与设备迁移。
- 文件损坏或密钥丢失时，阻止覆盖保存，保留文件并提供重试和明确确认后的清除入口。

当前调试版本为 `0.1.0-stage3.1`（`versionCode=3`），包名为 `io.github.tbeimu.gongxiaozhu.debug`。同一台开发机生成且签名相同的调试包可覆盖此前阶段调试版；调试版本与未来正式版本使用独立的包名和数据目录，暂不提供账号迁移。

## 第三阶段已实现

- 通过 Android 网络回调观察当前 WiFi，不依赖 SSID 或定位权限；未认证 WiFi 也可使用。HTTP SocketFactory 和 DNS 均绑定选定 WiFi，不使用系统默认网络、移动数据或系统代理。
- 自动模式探测公共／宿舍已知状态端点，并解析 JSON／JSONP 状态；普通网页或仅能连接主机不会视为校园网。两个端点均返回有效状态时，提示手动选择并保存网络模式，再手动登录。
- 公共 WiFi：先检查 wlgn 状态，未认证时提交默认账号，再复查状态；已认证时不退出、不再次提交密码。
- 宿舍 WiFi：先检查光猫网关及 lgn 状态；按需完成第一阶段认证和 lgn IPv4 二次认证，并复查状态。第一阶段已在线时仍检查二次认证，失败时提示阶段状态。
- 每次进入前台最多自动尝试一次，屏幕旋转不会增加自动尝试次数；失败或网络切换后等待手动重试。离开前台、WiFi 断开、地址／路由变化或网络模式修改时取消请求；单次流程不会并行或自动轮询账号。
- 登录开始时固定默认账号；修改默认账号只影响后续登录。通过校验后只读取选定账号，一次宿舍流程复用同一份凭据。
- HTTP 仅允许 `10.21.251.3`、`10.21.221.98`、`172.30.201.2`；认证端点、端口与路径由代码固定。禁止跳转、代理和自动重试；参数使用 UTF-8 编码，响应限制 128 KiB，单请求最多 8 秒，整体流程最多 45 秒。
- 首页显示连接状态、认证进度和中文失败提示，支持手动登录／重试。异常响应不直接显示服务端原文或带密码的 URL。

自动识别和协议解析以旧参考项目为依据。实际校园服务可能更改地址、参数、页面标记或响应格式，须通过下一阶段校园实测确认。目前 IPv4 二次认证使用 `172.30.201.2`，不自动尝试备用地址或 IPv6。

## 本地构建

需要 JDK 17 或 21、Android SDK Platform 36 和 Build Tools 36.0.0。已提交 Gradle Wrapper，无需单独安装 Gradle。

在项目根目录的 `local.properties` 配置 SDK 路径，例如 Windows：

```properties
sdk.dir=D\:/Applications/Development/Android/Sdk
```

Windows PowerShell：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

macOS／Linux：

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

安装包输出为 `app/build/outputs/apk/debug/app-debug.apk`，可复制到 Android 12 及以上手机安装。此阶段支持界面预览与校园联调，真实认证仍待验证。开发和模拟测试使用虚构账号。

连接安卓设备或启动模拟器后，可执行安卓端测试：

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest
```

安卓界面测试会清除调试版账号数据，请使用独立测试模拟器。多个设备同时连接时，先设置 `$env:ANDROID_SERIAL='<测试设备序列号>'`，可用 `adb devices` 查看序列号。

构建依赖采用已验证的固定版本组合。Lint 将其他警告视为错误；版本升级提示单独评估，不作为功能质量检查失败项。

### 第三阶段 review（0.1.0-stage3.1）

- 修复 HTTP 库在收到 `503 + Retry-After: 0` 后自动重发认证请求的问题。通过本地服务复现后，在 HTTP 库处理重试前终止该响应；GET 和 POST 登录均只发送一次。
- 修复 WiFi 初始快照可能选中带 WiFi 传输标记的 VPN，而网络回调又不观察该 VPN 的问题。初始快照与回调统一排除 VPN，继续允许未通过互联网认证的实体 WiFi。
- 修复宿舍二次认证连接失败／超时后丢失第一阶段状态的问题。错误提示保留已确认的第一阶段和网络类型；第一阶段状态未确认时不宣称完成。
- 58 个 JVM 测试、8 个 Android 12 独立模拟器测试、Lint 和 Debug APK 构建通过。新增测试覆盖 GET／POST 的 503 不重发、VPN 传输标记过滤、宿舍二次认证超时／连接失败及第一阶段未确认。
- Debug APK 签名验证通过；独立模拟器从 `0.1.0-stage3` 覆盖安装到 `0.1.0-stage3.1` 并冷启动成功。升级前后加密文件哈希一致，虚构测试账号和默认账号正常读取。
- VPN 过滤测试使用 Android 传输标记构造验证规则，未在真实手机上运行 VPN 联调。用户初步反馈尚不足以完成公共／宿舍校园实机验收，本次不配置正式发布。

## 验证目标

- 账号保存后，重启 App 仍可读取；增删改及默认账号切换正常。
- 密码中的特殊字符正确编码，日志不记录密码或完整登录 URL。
- 公共 WiFi 和宿舍两阶段认证正确处理成功、已登录、密码错误、超时和异常响应。
- 无 WiFi、普通 WiFi、移动数据同时开启、网络切换和重复打开 App 时行为明确。
- 校园实机验证：保存一次账号后，再次打开 App 无需填写账号密码即可完成认证。
- 发布后验证手机 APK 下载、安装及覆盖更新。

## 凭据与网络

真实账号密码、签名密钥及其口令不得提交到仓库。发布签名所需机密将通过 GitHub Actions Secrets 配置；本机 SDK 路径、缓存和构建产物由 `.gitignore` 排除。

登录凭据仅发往已知校园认证地址，携带凭据的请求禁止自动跳转到其他地址。学校参考协议使用 HTTP，本地加密只保护手机中的账号存储，不改变网络传输方式。
